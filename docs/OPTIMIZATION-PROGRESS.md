# 优化实施记录

开始日期：2026-10-09；最近更新：2026-10-11。源码目录：`Z80Z-chat-build`。

## 第一批：基础修复与聊天体验

首批覆盖阶段 0 的基础修复，以及阶段 1 的消息列表和输入框。桌面、移动聊天的交互设计预览用于确定后续整体视觉方向；实际应用本批沿用现有色板，先改善消息密度、回复摘要、附件卡片和操作入口。

已实施：

- 同作者、同频道、同日、5 分钟内连续消息合并头像与昵称；回复消息打断分组，保留每条消息时间。
- 日期分隔、可点击消息菜单、已加载原消息的回复摘要；菜单独立于消息动画和滚动区，支持键盘焦点及 Escape 关闭；编辑失败保留内容并显示错误。
- 阅读历史时收到新消息保持位置，显示数量和“回到最新”；加载旧消息按可见消息锚点恢复位置。
- 窗口和输入区高度变化时，原本正在跟随最新消息的列表继续保持底部位置。
- 按账号、频道保存文字及回复草稿；输入法确认 Enter 不发送，Shift + Enter 换行。
- 发送中禁止再次提交；失败保留内容并提示先核对记录，成功只清理对应提交时的草稿。
- 图片和文件先预览再发送；消息提交失败后复用已上传结果。附件仅在当前页面内缓存，最多 5 个频道，刷新后需重新选择。
- 主动退出停止重连，旧连接事件不能影响新连接；启动时先激活连接，让频道订阅可以排队。
- 返回主页重新订阅当前频道，监听安装不等待服务器列表；消息编辑和删除广播更新列表。重连刷新使用服务器最新完整窗口，只叠加请求期间的实时事件，防止旧正文覆盖服务器结果或已删除消息重新出现。
- 同毫秒发送的消息按插入顺序分页，避免分页边界遗漏或重复。
- 消息加载失败显示错误和重新加载入口，不显示为普通空频道；账号尚未确认时显示加载提示并暂不允许输入。
- 历史附件过期后重新签名；随机签名密钥必须可靠持久化，取消固定密钥回退。
- 中文附件名称按上传编码还原，兼容 ASCII、重音、emoji、已经解析的 Unicode 和旧 Latin-1 名称，发送和历史记录保留显示名称。
- 数据库写入失败保留待保存状态，延迟重试；明确保存失败仍向调用方报告错误。

第一批的页面内新消息计数和重试能力，已由下面第二批的服务端确认及阅读状态继续完善。

## 第二批：发送确认与持久化未读

日期：2026-10-09。已实施并验收：

- REST 与 WebSocket 共用发送逻辑，以账号和 `clientMessageId` 唯一记录发送结果。消息与发送凭据一起落盘后才确认；同 ID、同内容重试返回原消息，不重复创建或广播。
- 已编辑消息的重试返回现有消息；不同内容复用 ID 返回 409，已删除消息重试返回 410，保留删除后的凭据防止旧发送重新创建消息。重试仍检查当前成员、禁言、查看和发送权限。
- 输入框显示发送中、未确认和手动重试状态。只有返回消息 ID、提交 ID、频道和稳定序号有效时才清理草稿；超时、无效确认和旧账号响应均不会误清草稿。请求超过 15 秒取消等待，提示未确认结果。
- 未确认的文字、回复与已上传附件信息按账号和频道保存。同一内容刷新后继续使用原 ID 重试，附件复用上传结果。原始文件和未上传附件仍只在当前页面缓存；浏览器存储失败时明确提示刷新前核对记录。
- 旧数据库升级前保存原始内容备份，为历史消息补稳定递增序号；现有成员的历史记录作为初始已读基线。迁移写入失败保留原数据库并停止启动，不静默丢弃旧数据。
- 阅读游标由服务端按账号和频道持久化，使用消息 ID 验证所属频道并单调更新；新消息、删除和阅读确认后，未读元数据推送到该账号的所有连接，重连补拉。
- 频道列表显示未读数量，当前频道显示新消息分隔线。自己的消息不增加未读；页面处于前台并获得焦点、对应消息底部在可见范围内停留 500ms 后才申请阅读确认，浏览历史或后台标签页不会直接清除最新未读。
- 迟到的请求或推送不会倒退游标、恢复已移除频道或污染另一个账号。同步失败保留当前未读并提供重新同步入口。
- 每次消息、编辑、删除和未读推送重新检查接收连接的会话、成员身份与查看权限；踢出、撤权、注销和过期后，即使保留旧频道订阅也不再接收这些数据。
- 原子保存不忽略 `fsync` 失败；磁盘同步失败时关闭文件描述符、保留旧数据库和待写状态，不返回发送成功。删除落盘失败时同 ID 重试保持未确认，删除保存后才返回 410。

阶段 1 的视觉与移动操作继续在第三批交付。实体手机软键盘验收仍待进行。消息先显示明确提交状态，成功后插入确认消息，尚未加入列表内的临时消息气泡。回复定位暂限已加载消息；原消息上下文、回应、置顶和搜索按后续阶段实施。

## 第三批：主聊天视觉与移动操作

日期：2026-10-09。已实施：

- 全局建立颜色、文字、4px 基准间距、圆角、阴影和层级变量；现有 Tailwind 颜色映射保留透明度支持。主聊天页采用单一蓝紫导航强调色，成功与危险状态配合文字；启动背景与主题色一致。
- 统一聊天头部、导航选中和未读状态、15px 消息正文、回复摘要、文件卡片、错误及空频道、输入框和反馈。桌面消息操作在悬停或键盘聚焦时显示，手机保留明确入口。
- 桌面文字频道的成员栏可收起，偏好保存在当前浏览器；小于 1280px 的首次进入默认留更多聊天空间，语音页保留成员栏。服务器、频道、分类及成员入口可使用 Enter 或 Space；隐藏的抽屉使用 inert 防止键盘进入屏幕外内容。
- 手机长按消息 500ms，或点击消息操作按钮打开底部面板；显示作者、完整时间和内容摘要，支持回复、本人文字编辑、本人消息删除和取消。删除保留确认，面板支持焦点循环与 Escape，关闭后恢复触发位置。
- 移动超过 10px、滑动、额外触摸、松手、滚动、失焦、隐藏、换频道、换账号和卸载会取消待触发长按。长按释放产生的合成点击会被拦截，避免误开附件或误点新面板按钮；下一次主动点击与键盘操作正常生效。
- 面板打开期间暂停背景消息的阅读确认，关闭后重新等待可见停留时间；消息被远端删除后关闭面板。
- 主要移动按钮至少 44px，面板操作至少 48px；支持安全区域和减少动画。输入区使用 VisualViewport 的高度与平移量，模拟键盘缩小时隐藏底部服务器导航，失焦或恢复后显示；手机输入文字为 16px，缩放不误判为键盘。

本批完成阶段 1 的核心视觉与移动操作。实体手机、浏览器软键盘和真实两设备通话仍需实机验收；后续进入阶段 2 的回应、置顶、回复定位与搜索。

## 第四批：消息回应、置顶和找回

日期：2026-10-09。阶段 2 的首批功能已实施：

- 提供赞、喜欢、好笑、庆祝、惊讶、难过六种消息回应。显示服务端人数、本人选中状态和回应成员名单；同一表情每人只计一次，重复请求保留目标状态。失败可重试，禁言、离服或没有查看和发送权限时不能添加或撤销回应。
- 有管理消息权限的成员可置顶或取消置顶。频道头部面板显示正文或附件摘要、作者、置顶操作者和时间，点击可定位；删除消息自动移除置顶及回应。
- 频道内按正文或文件名关键词、发送者查询，支持只筛选发送者、稳定顺序游标分页和明确的加载、空结果及错误状态。文字查询按字面量匹配，最多 100 个字符；服务端每账号每 10 秒允许 20 次查询，并检查当前成员与查看权限。
- 点击回复摘要、置顶或搜索结果可获取目标消息前后最多 50 条上下文，定位并高亮原消息；删除或权限失效时显示明确错误。定位期间的新消息单独计数，不跨历史缺口拼入当前窗口；“回到最新”重新加载最新窗口。关闭搜索面板可取消未完成的定位，迟到响应不再替换记录或抢走焦点。
- 回应、置顶和编辑先落盘再广播完整消息；保存失败恢复原记录及版本。消息版本递增，客户端丢弃较旧的回执或推送。查询期间叠加实时编辑与删除，刷新和重连重新拉取，防止旧正文、旧置顶或已删除结果恢复。
- 编辑和删除补齐当前成员与查看权限检查；退出服务器后不能继续修改原来发送的消息。回应和查询请求隔离账号、会话、频道和卸载后的迟到结果。
- 新面板与回应采用统一语义样式，支持焦点、Escape、面板 Tab 循环、移动 44px 触摸按钮、安全区和减少动画。面板打开期间暂停背景消息的已读确认。

旧消息的回应、置顶和版本在响应时补默认值，无需重写历史数据库；用户与置顶操作者只返回公开资料。回应参与者资料在读取时解析，不在消息中复制账号或凭据。

本批没有加入成员提及选择器与跨频道提醒；它们在下面第五批继续实施。搜索当前使用 JSON 存储的内存扫描，数据量扩大时仍需迁移并建立索引。

## 第五批：成员提及与应用内通知

日期：2026-10-09。阶段 2 核心功能已实施：

- 输入 `@` 后按昵称或用户名选择当前社区成员，同昵称显示用户名以便区分；支持键盘上下选择、Enter 选择而不发送、Escape 关闭和中文输入法。全体成员候选受角色权限控制，手写独立 `@everyone` 同样由服务端检查。
- 提及按成员 ID 保存，输入框和正文显示昵称。草稿与未确认发送按账号、频道保留身份，昵称变化不改变收件人；重复同名文字的删除、粘贴及撤销不会误提及另一个成员。未选择的普通 `@名称` 保留文字。
- 被提及消息使用独立背景与文字强调，点击已解析成员可打开资料；回复摘要、搜索、通知和编辑显示可读昵称。编辑保留既有身份，修改提及文字取消身份；昵称搜索跟随公开资料变化。
- 发送先落盘再向收件人的所有有效登录连接定向推送，覆盖其他频道和社区；排除自己，并逐连接检查当前会话、成员身份及查看权限。同编号重试不重复提醒；兼容旧发送凭据和收件人离服后的原消息确认。
- 提供应用内通知面板和铃铛计数，按稳定序号分页。离线未读从消息及持久阅读游标恢复，重启后仍可查看；编辑刷新内容，删除清理提醒。资料仅返回公开字段，旧记录在响应时补默认值。
- 每个账号、频道可选择所有消息、仅提及或静音，默认仅提及；设置落盘后同步到同账号其他会话，保存失败恢复原值。频道提及徽标单独计数，静音不改变普通未读消息数量。
- 点击通知可切换社区、频道并定位原消息；打开面板及等待定位时暂停背景已读，真正读到消息后同步清除各会话提醒。权限失效、删除和定位失败有明确提示；手动切换和旧请求不会抢回导航。
- 面板使用全局样式，支持焦点恢复、Tab 循环、Escape、44px 主要触摸目标及安全区域；提及候选在手机至少 48px。频道名在窄屏可截断，完整文字仍保留在可访问名称中。

本批提醒通过应用内面板提供，尚未加入系统通知、声音或通知点击即全部已读。通知查询仍依赖 JSON 内存扫描；语音设备与发言控制在下面第六批继续实施。

## 第六批：语音设备与发言控制

日期：2026-10-09。阶段 3 首批已实施：

- 入房前与通话中可主动测试麦克风电平或播放本地扬声器测试音；两种测试互斥，显示开始、停止、权限失败与设备断开状态。测试模块不加入语音房间，也不把测试流接入通话。通话中的原有麦克风仍遵守当前发言方式与静音状态。
- 测试停止、设备变化、失焦、页面隐藏或组件卸载后释放采集、音频节点、播放元素和计时器。迟到的采集、输出切换和播放结果不能重新启动测试。浏览器不支持输出设备选择时提示使用系统默认输出。
- 授权后的设备枚举识别默认设备别名及实际采集设备，不再把 ID 补全误判为设备切换；枚举扬声器不会终止麦克风测试，真正切换当前测试设备仍释放旧资源。
- 单独调整每个远端成员的播放音量，范围 0–100%；与总输出音量相乘，静音喇叭后恢复原偏好。成员音量、总输出、发言方式与快捷键按账号保存在本机，切账号时隔离；不会影响其他成员的音量设置。
- 支持开放麦克风与按键发言，快捷键可配置；输入框、中文输入法选字及组合键不触发发言。手机可按住按钮说话，松手、触摸取消、失去捕获、失焦、页面隐藏、离房和连接中断都释放发言状态。快捷键仅在网页前台生效。
- 原始和处理后的麦克风发送轨同步遵守静音、喇叭静音、按键状态、设备切换和信令连接状态。刷新恢复语音时先恢复静音标记再建链，换房保留手动静音；麦克风断开后关闭发送并提供重新检测入口。
- 入房、重连、信令、设备切换和投屏异步操作检查当前账号、令牌、房间及会话版本；离房或换账号后的迟到结果不能恢复旧房间。断线期间不排队重放旧语音房间控制，成员离开时清理连接、候选、播放重试和元素。停止投屏不再移除该成员的语音播放。
- 原有本地进出房音效使用独立播放资源，遵守总音量和喇叭静音，离房时清理。输出设备切换按播放元素串行应用，旧请求晚完成不会覆盖最新选择。
- 音频设置、成员音量和设备测试拆为独立组件；设备测试、偏好和快捷键处理拆为工具模块。样式统一在全局样式文件，提供明确发言文字、焦点反馈、44px 主要控件及 48px 按住发言按钮。

本批完成语音设备和发言控制；影院与诊断在下面第七批继续实施。PeerConnection、投屏和统计尚未完全从 voice.ts 分离。浏览器使用模拟麦克风验证发送轨控制与本地 WebRTC，尚未验证实体设备听感、蓝牙切换、网络通话质量或投屏画面。

## 第七批：投屏影院与连接诊断

日期：2026-10-09 至 2026-10-10。阶段 3 的投屏与诊断已实施：

- 投屏画面区统一显示本地预览及远端共享，可观看全部画面或指定成员。选择按用户 ID 保持，改名、同名和排序变化不改变所选成员；共享停止时回退到有效画面。切换时保留播放器实例，未选中的播放器暂停呈现，不停止传入媒体轨。
- 影院模式收起服务器、频道、成员及手机底部导航，退出恢复原布局；保留静音、喇叭静音、离开、停止共享与手机按住发言入口。进入聚焦返回按钮，返回或 Escape 恢复焦点；最后画面结束、换频道、离房或换账号时自动退出，影院切换不挂断语音。
- 影院画面区与通话控制条分别占用布局空间，窄屏控制条换行后不会覆盖播放或全屏按钮；原生全屏填满浏览器视口，视频仍保持比例。
- 本地与远端画面使用统一播放组件，保留原共享画质、帧率和窗口切换。视频控制条只提供播放/暂停与全屏；全屏保持比例，浏览器拒绝时显示可读错误。播放器不会替用户停止共享轨。
- 手动暂停在切换观看画面及重新绑定共享流后保留。播放承诺、重试、帧回调、媒体及轨道事件按绑定版本失效；隐藏、未选中、换流或卸载后的旧结果不能自动恢复播放，取消的全屏请求晚成功会退出。
- 播放状态区分等待、加载、浏览器阻止、用户暂停、无可播放数据、共享结束和错误。静态或黑色但已解码的画面不再被时间差误判为黑屏；没有帧统计接口时呈现帧数及帧率显示缺失值。
- 连接诊断按成员展示连接与 ICE 状态、选中的通路类型及协议、往返延迟、语音/视频码率和丢包，以及视频收到、解码与播放器呈现。缺失值显示“未提供”，未建立采样基线时不估算码率，不显示地址、SDP、令牌或原始错误。
- 详细诊断仅在打开面板时解析现有统计结果，复用单次 `getStats` 采集；旧请求、换房、换账号和连接替换不会污染新记录。基线按成员和 RTP 报告隔离，浏览器计数回退后重建；播放器上报同时核对当前共享流。
- 统计优先关联当前发送、接收轨道，排除明确属于旧轨道或已经失活的 RTP 条目。自动码率使用实际投屏接收方选中通路的延迟与接收反馈；任一明确较差连接可降档，所有实际接收方连续健康才恢复，缺少反馈不当作零丢包而升档。
- 诊断面板支持焦点循环、Escape、关闭恢复和移动安全区域；打开后背景不可聚焦且按键发言不触发。画面选择、影院返回、视频控制、诊断关闭和主要通话按钮至少 44px。
- 共享刷新只作用于目标成员，同一成员的刷新请求不会并行重协商。延迟共享开始通知受房间与账号保护，停止共享、成员离开、重连、切换或卸载取消旧任务；其他房间的停止事件不能移除当前画面。

本批没有完全拆出 PeerConnection、共享采集或信令调度。多人大房间仍使用现有 WebRTC mesh；没有新支持人数或公网性能结论。真实两设备音视频、浏览器共享选择器、蓝牙、手机原生全屏及网络质量仍需实机验收，安装版尚未更新。

## 第九批：连接、协商与投屏核心拆分

日期：2026-10-10。阶段 3 的语音核心拆分继续实施，保持现有页面接口与通话控制：

- `utils/voice-peers.ts` 管理 ICE 配置缓存及并发加载、PeerConnection 创建与关闭、重试计时器和次数。连接失败最多按 2、4、6 秒延迟重试，连接成功或清理后重置；已排队的旧回调不能删除同一成员新连接的重试任务。
- `utils/voice-signaling.ts` 管理 offer/answer、礼貌方回退、候选缓冲、初次建连与定向投屏刷新。候选队列绑定具体连接，投屏期间为重连成员重建连接时完整释放候选、刷新标记和重试资源；迟到的旧协商不能答复新房间或污染新连接。
- `utils/voice-screen-share.ts` 管理本地共享采集、画质与帧率、按接收方健康反馈调整码率、切换来源和停止共享。保留原有 H264/VP8 编解码器优先次序、比例限制和目标刷新行为；此次拆分没有改变 WebRTC mesh 拓扑。
