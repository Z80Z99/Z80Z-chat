# 单文件部署模式（Z80Z-chat.bat）

Z80Z-chat 可打包为单个 `Z80Z-chat.bat`，内含引导层、管理入口和源码 ZIP。
双击后选择安装目录，按需下载 Node.js，再安装依赖、检查并构建前端，之后进入管理菜单。
文件大小随源码与文档变化，不包含 Node.js 二进制、依赖目录或前端构建产物。

## 运行结构

建议将 `Z80Z-chat.bat` 放入一个**空白文件夹**，首次双击完成安装后目录结构如下：

```
部署文件夹/
├── Z80Z-chat.bat        # 单文件安装程序（以后双击 = 管理菜单）
├── nodejs/             # 自带的 Node.js 运行时（选择"自动下载"时生成）
├── data-backup/        # 外层数据备份目录（更新时自动备份）
└── z80z-chat/           # 项目本体（start.js / config.json / data/ …）
```

- 项目文件夹名可在首次安装时指定（默认 `z80z-chat`）
- 卸载前停止服务与隧道并保留所需数据；使用自定义外部数据目录时，数据不一定在部署文件夹内
- 再次双击 `Z80Z-chat.bat` 会自动发现已安装项目并进入管理菜单

## 安装流程（首次双击）

1. 选择 Node.js 来源：
   - **使用系统 Node.js** —— 检测到 PATH 中已有 Node ≥ 18 时提供
   - **自动下载自带 nodejs/** —— 下载到部署目录，不修改系统 Node.js
   - 手动下载（提供教程）
2. 选择网络线路（自动测速，Node.js 下载与 npm 安装共用的镜像线路）
3. 设置端口（留空自动选择随机可用端口 10000-60000）
4. 自动完成：释放项目 → `npm ci --include=dev` → `npm run check:frontend`

源码 ZIP 包含 `package-lock.json` 和 `start.js`，按锁文件安装运行与构建依赖。
`check:frontend` 依次检查 Vue 模板及 Vite 配置类型、生成 `dist/`、检查界面规则；步骤失败时不继续启动。

## 配置承载（v1.0.8+）

所有部署配置统一存放在项目内 **`config.json`**（带中文注释，记事本可编辑），
**不再使用外层 `.install-config.json`**（旧版残留会在安装/更新时自动吸收并删除）。

| 字段 | 作用 |
|------|------|
| `backupKeep` | 自动清理旧备份时保留的份数（默认 3） |
| `nodeVersion` | 自动下载 Node.js 使用的主版本（默认 22；旧系统回退分支的验收边界见下文） |
| `nodeMirror` | Node.js 下载镜像（安装时选择线路后自动写入） |
| `npmRegistry` | npm 镜像源（安装时选择线路后自动写入） |
| `port` / `host` 等 | 服务监听配置（原有字段不变） |

## 更新流程

- 将新版 `Z80Z-chat.bat` 覆盖部署文件夹中的旧版，再双击运行
- 版本或内容指纹变化时提示更新，符合快速更新条件时可跳过重新安装与构建。
- 完整更新先在外层 `.update-stage-<随机编号>` 目录解压源码、复制当前配置，再执行真实的 `npm ci --include=dev` 与 `npm run check:frontend`。准备失败时当前项目文件保持原样。
- 新版准备成功后才停止服务，按实际 `dataDir` 备份数据，再事务替换项目文件。`config.json`、数据与日志保留在项目中；完整更新安装新版依赖和 `dist/`，快速更新沿用原有两者。
- 数据目录按 `DATA_DIR` 环境变量、`config.json` 的 `dataDir`、默认 `data/` 的优先次序解析。项目内的自定义相对目录予以保留，项目外的绝对目录不参与换码；备份包含 `.upload-secret` 等隐藏文件。
- 文件提交失败时恢复旧代码、依赖、构建产物和安装标记。若文件占用等原因阻断恢复，错误会给出保留的 `.project-rollback-<随机编号>` 路径；不要删除该目录，停止相关进程、解除占用后，按保留文件恢复。旧文件可能分别位于项目目录和回退目录中。
- 更新成功后，项目文件夹的版本尾缀可同步为新版。若 `dataDir`、`DATA_DIR` 或 `LOG_DIR` 使用项目内部的绝对路径，则保留原目录名，避免原路径失效。改名被占用或权限阻止时也保留原名，管理入口继续指向实际目录；已提交的新版代码不因改名失败回退。

更新成功后仍需启动并检查服务。事务保障的是文件替换与失败恢复，不代替登录、历史数据和实际设备的运行验收。升级前应另行保存完整数据备份。

## 备份管理

- 主菜单「备份管理」：立即备份 / 查看 / 恢复 / 清理，备份存于外层 `data-backup/`
- 完整更新在停止服务后自动备份实际数据目录，包含隐藏文件；快速更新不新增数据备份
- 保留份数由 `config.json` 的 `backupKeep` 控制，仅清理已识别的旧备份目录

## 公网访问（隧道管理）

- 无公网 IP 也能对外访问：主菜单「隧道管理」→ 选择服务（Cloudflare Tunnel / SakuraFRP）
- **Cloudflare Tunnel**：按向导登录、创建隧道并绑定自己的域名，cloudflared 按需下载到外层 `cloudflared/` 目录（下载前测速选择线路）
- **SakuraFRP**：需服务账号，frpc 下载链接从面板「软件下载」复制粘贴，隧道在面板创建（本地 IP 127.0.0.1，端口 = Z80Z-chat 端口），连接方式支持交互（frpc TUI）与命令行（`-f 密钥:隧道ID`）两种
- 两者均为后台运行 + PID 记录，互不影响，与 Z80Z-chat 服务独立

## 智能快速更新

- 安装器先重新计算内嵌源码 ZIP 的内容指纹并与引导层记录核对，再比较当前 `.install-version` 中的指纹与生产 / 开发依赖键。
- 仅当源码指纹和依赖键一致，且当前 `node_modules/.bin/vite.cmd` 与 `dist/index.html` 存在时，才采用快速更新：准备源码 → 停服 → 事务换码，保留现有依赖与构建产物，不执行 npm 安装、构建或数据备份。
- `start.js` 和 `package-lock.json` 都参与源码指纹；修改它们同样会触发完整更新。缺少指纹、依赖工具或构建入口时也走完整更新。
- 指纹只排除源码 ZIP 中的 `package.json`，依赖变化另行比较；锁文件变化仍会改变指纹。不能根据“只改版本号”推定会进入快速更新。

## 兼容性

- 本轮在当前 Windows 与 Windows PowerShell 环境验收安装器事务；未验证 Windows 7 / 8、PowerShell 2 或旧版 Node.js 的安装与构建兼容性
- 引导层保留旧 Windows 检测、PowerShell 兼容处理及 Node.js 18 回退分支；保留分支不代表这些环境已通过验收
- 首次部署若选择「使用系统 Node.js」，之后运行会自动沿用（无需持久化记录）

v1.0.9 已完成本地构建及隔离安装、升级验收，尚未发布 GitHub Release，也未替换已有真实安装副本。实体设备和公网语音 / 投屏仍待独立验收。

## 常见问题

- **杀毒软件报毒/拦截**：单文件 bat 内含自解压逻辑，部分杀软（尤其 360/火绒）
  会误报。可加信任白名单，或手动方式运行（见下）。
- **下载缓慢**：换线路（安装时测速选择，或编辑 `config.json` 的镜像字段后重跑更新）。
- **UAC 弹窗**：启动服务时若开启防火墙配置会请求管理员授权，拒绝仅警告不中断。
- **手动方式**：不用单文件也可直接 `node start.js` 管理（需自行安装 Node.js）。

## 构建

```bash
npm run build:single    # 或 node scripts/build-single.js
```

- 输出：项目根目录 `Z80Z-chat.bat`（版本号取自 package.json）
- 打包内容：引导层（`deploy/install.template.bat`）+ 内嵌管理入口 + 项目源码 ZIP；ZIP 包含 `start.js`、`package-lock.json`、前端源码和验收脚本
- 排除：`node_modules/`、`dist/`、运行数据与日志、测试临时目录、隧道账号目录、环境文件、签名密钥、安装标记、`*.tsbuildinfo`、`start.bat`、模板和构建产物自身；配置与环境指定的项目内运行目录也予以排除
- 构建前检查发布配置，拒绝私有上传签名密钥或私有 ICE 账号；使用不含部署者凭据的分发配置，检查过程不改写原配置
